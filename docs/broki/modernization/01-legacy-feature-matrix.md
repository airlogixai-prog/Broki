# 01 — Matriz de paridad legacy (`broki.html` / `registrobroki.html`) → Next

Fuente de verdad: lectura directa del código legacy (4 auditorías independientes, 2026-10-11) contrastada con `web/src/**` y `supabase/functions/**`. **Estados actualizados 2026-10-14** con la evidencia de `06-qa-evidence.md` (local, Supabase desechable).  
Estados: `FULL_PASS` (verificado hoy con test/ejecución), `INTENTIONAL_IMPROVEMENT` (legacy documentado, mejora justificada), `BLOCKED` (dependencia externa), `UNVERIFIED` (código inspeccionado, sin prueba ejecutada aún). **Solo se eleva a FULL_PASS tras evidencia en `06-qa-evidence.md`.**

Prioridad: P0 = operativa diaria / pérdida de datos / seguridad; P1 = utilidad relevante; P2 = pulido.

## Hallazgos clave del legacy (corrigen los inventarios previos)

- `cambiarTab`, `openDetail`, `sendWebhook` están definidos varias veces; solo la última definición corre. `normalizeFurgo/normalizeGSE/calculatePressures/calculateGPUFuel` son código muerto.
- `getStatusCategory` legacy clasifica `INOPERATIVO` como *available* (bug de substring). Next ya lo corrige (orden occupied→inoperative→available).
- `row.parking` nunca se mapea en legacy: "Parking" siempre vacío; "Ubicación" = `ubicacion_habitual`.
- Historial de uso en el modal legacy = **datos mock** (nombres inventados).
- Planner: sin selector de día (solo hoy), sin parseo PDF en cliente (el PDF va crudo a n8n), sin previsualización, borrado de grupo roto para ids string, PIN `XXXX` solo protege el panel de creación.
- Roster: **datos hardcodeados** (15 personas mock), cabeceras de día fijas, aerolínea por índice de fila; el PDF se sube y nunca vuelve a la pantalla.
- Relevos: solo `localStorage.relays_db`, borrado por índice, XSS almacenado.
- Mapa: Leaflet cargado pero no usado; `<img>` estáticas de 8–43 MB; solo pinta equipos `occupied`; un solo color.
- Analítica: ApexCharts sin pin; "chart-fuel" es una lista HTML; donut excluye incidencias abiertas.
- Stock N₂: dos terminales hardcodeadas (`t4s`, `t1,2,3`), matching por string, sin validación, refresh 30 s pisa la edición.
- Tooling: sin pantalla de catálogo; sin fabricante/proveedor; check-in puede mostrar éxito sin POST; `movementId` obsoleto reutilizable; U/S no bloquea sacada.
- Registro: sin honeypot, sin duplicados, sin estado "pendiente".
